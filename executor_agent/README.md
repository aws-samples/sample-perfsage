# PerfSage — Executor Agent (Agent 2)

AI-powered load test execution engine. Receives k6 scripts from the TestGen Agent, provisions AWS Fargate infrastructure, executes tests, streams real-time metrics, detects anomalies, and persists results for the Analysis Agent.

---

## How It Fits

```
TestGen Agent (Agent 1)  →  Executor Agent (Agent 2)  →  Analysis Agent (Agent 3)
   generates k6 script        runs it on Fargate           interprets results
```

- **Input:** k6 script (from Agent 1 or manually written)
- **Output:** Raw metrics in S3 + summary in DynamoDB (consumed by Agent 3)

## Quick Start

### 1. Install

```bash
cd executor_agent
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

### 2. Deploy Infrastructure

```bash
perfsage-executor deploy
```

This single command:

- Checks all prerequisites
- Validates AWS credentials
- Bootstraps CDK (first time only)
- Deploys 3 CloudFormation stacks (Storage, Networking, Execution)
- Builds and pushes the k6 Docker image to ECR
- Auto-generates `.env` with all resource IDs

### 3. Run a Test

```bash
# Quick test with sample script
perfsage-executor run -s tests/fixtures/sample_k6_script.js --vus 10 --duration 1m

# Run a script generated by Agent 1
perfsage-executor run -s path/to/loadtest.js --vus 100 --duration 5m

# With custom target URL
perfsage-executor run -s loadtest.js --vus 50 --duration 3m --target-url https://your-api.com
```

### 4. Check Results

```bash
perfsage-executor status --test-id <test-id>
perfsage-executor list
```

### 5. Destroy (when done)

```bash
perfsage-executor destroy
```

## Architecture

```
┌──────────────────────────────────────────────────────┐
│               Executor Agent (Strands)               │
│                                                      │
│  Tools: provision → execute → stream → detect → end  │
│                                                      │
│  ┌──────────┐  ┌──────────┐  ┌───────────────────┐  │
│  │  Docker  │  │ Fargate  │  │ WebSocket + CW    │  │
│  │ (local)  │  │  (AWS)   │  │ (real-time)       │  │
│  └──────────┘  └──────────┘  └───────────────────┘  │
│                                                      │
│  ┌───────────────────────────────────────────────┐   │
│  │  S3 (raw metrics) + DynamoDB (summaries)      │   │
│  └───────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────┘
```

### CloudFormation Stacks

| Stack                | Resources                                               |
| -------------------- | ------------------------------------------------------- |
| `PerfSageStorage`    | S3 bucket, DynamoDB tables (test-runs, ws-connections)  |
| `PerfSageNetworking` | VPC (2 AZs), WebSocket API Gateway, Lambda handlers     |
| `PerfSageExecution`  | ECS cluster, ECR repository, IAM roles, Security groups |

## Output for Agent 3 (Analysis)

After execution, results are available at:

- **S3:** `s3://perfsage-results-{account}-{region}/runs/{test-id}/metrics.json` (raw k6 data)
- **S3:** `s3://perfsage-results-{account}-{region}/runs/{test-id}/summary.json` (aggregated)
- **DynamoDB:** `perfsage-test-runs` table (test metadata, status, summary stats)

## Anomaly Detection

Built-in rule-based detection during test execution:

- **Threshold breach** — p99 latency or error rate exceeds limits
- **Sudden spike** — Latency jumps 3x+ in 10 seconds
- **Error burst** — Error rate surges from <1% to >5%
- **Connection exhaustion** — Rising errors + latency simultaneously
- **Flatline** — 0 RPS with active VUs (target down)

## Configuration

After `perfsage-executor deploy`, `.env` is auto-generated. Key settings:

| Variable                     | Description                        | Default                        |
| ---------------------------- | ---------------------------------- | ------------------------------ |
| `PERFSAGE_EXECUTION_MODE`    | `local` or `fargate`               | `fargate` (after deploy)       |
| `PERFSAGE_MODEL_ID`          | Bedrock model for the agent        | `us.anthropic.claude-opus-4-7` |
| `PERFSAGE_ANOMALY_AUTO_STOP` | Auto-terminate on critical anomaly | `true`                         |
| `PERFSAGE_LOG_LEVEL`         | Logging verbosity                  | `INFO`                         |

| Per test run (5 min, 100 VUs) | Cost       |
| ----------------------------- | ---------- |
| Fargate (1 vCPU, 2GB)         | ~$0.03     |
| Bedrock (agent orchestration) | ~$0.05     |
| S3 + DynamoDB                 | ~$0.001    |
| **Total**                     | **~$0.08** |

## Troubleshooting

| Issue                                  | Fix                                                                                |
| -------------------------------------- | ---------------------------------------------------------------------------------- |
| `perfsage-executor: command not found` | `source .venv/bin/activate`                                                        |
| Deploy fails at CDK                    | Check `aws sts get-caller-identity` works                                          |
| Model ID invalid                       | Update `PERFSAGE_MODEL_ID` in `.env` — check Bedrock model access                  |
| Test shows 0 requests                  | Target URL unreachable from Fargate VPC — use public endpoint                      |
| `exec format error` in logs            | Rebuild image: `docker build --platform linux/amd64 -f ../docker/Dockerfile.k6 ..` |
| Expired AWS credentials                | Refresh and re-export, or run `aws configure`                                      |
