# Contributing Guidelines

Thank you for your interest in contributing to PerfSage. Whether it's a bug report, new feature, correction, or additional documentation, your feedback and contributions are valued.

## Reporting Bugs / Feature Requests

Use the GitHub issue tracker to report bugs or suggest features. When filing an issue, please check existing issues to avoid duplicates and include:

- A reproducible test case or series of steps
- The version of the code being used
- Any modifications you've made
- Details of your environment (OS, Python version, Node version)

## Contributing via Pull Requests

1. Check for open issues or create a new one to discuss what you'd like to change
2. Fork the repository and create your branch from `main`
3. Make your changes — keep them focused on a single concern
4. Ensure local tests pass (`brazil-build release` or equivalent)
5. Write clear, descriptive commit messages
6. Open a pull request and engage with CI feedback

For significant changes, please open an issue first to discuss the approach.

## Finding Contributions to Work On

Look for issues tagged with `help wanted` or `good first issue` — these are great starting points.

## Code of Conduct

This project has adopted the [Amazon Open Source Code of Conduct](https://aws.github.io/code-of-conduct). For questions or concerns, contact opensource-codeofconduct@amazon.com.

## Security Issue Notifications

If you discover a potential security issue, please notify AWS Security via the [vulnerability reporting page](http://aws.amazon.com/security/vulnerability-reporting/). Please do **not** create a public issue.
